# 08 リスク

## 1. 法務・コンプライアンス（最重要）

| リスク | 内容 | 対応 |
|---|---|---|
| スクレイピングToS違反 | メルカリ/ヤフオク等の自動取得が各社規約に抵触する恐れ | `04`で合法性を確認するまで案A未実装。数値統計のみ・出所明示・キャッシュ最小に限定 |
| 著作権（書影・本文・説明文） | 商品画像/出品説明の転載は著作権・不競法リスク | 他者の画像/本文は転載しない。書影は**ライセンスされたAPI**（openBD等）から。漫画本文は一切扱わない |
| 個人情報保護 | ユーザーのメール・コレクション・写真の管理 | 退会/削除対応(FR-C4)、最小収集、TLS、アクセス制御。プライバシーポリシー整備 |
| 古物営業法 | **将来マーケットプレイス化した場合**、古物商許可・本人確認等が必要になりうる | 売買は別フェーズ。やる場合は事前に法令確認。MVPは売買しない＝対象外 |
| 資金決済/特商法 | 決済を持つ場合の規制 | 同上。MVPは決済なし |
| 相場情報の正確性 | 「相場」を断定的に出すと誤誘導・苦情リスク | 「参考値・情報提供のみ・価格は変動」の免責明示（hobipediaも同様） |

## 2. データ・技術

| リスク | 対応 |
|---|---|
| 相場ソースの仕様変更/遮断で収集停止 | ソースを多重化、手入力(案C)/自己申告(案D)をフォールバックに |
| 名寄せ（同定）精度が低い | ISBN/JAN優先、状態フラグ＋著者で補完、フェーズ2で設計（`03`） |
| 画像肥大でストレージ/コスト増 | 自動縮小（デモ済み）＋枚数/容量上限 |
| localStorage→DB移行でのデータ欠損 | エクスポート常設、移行は非破壊ステップ（`05`） |

## 3. 事業・運用

| リスク | 対応 |
|---|---|
| データ未蓄積で相場の価値が出ない（コールドスタート） | MVPは管理機能の価値単体で成立させる。相場は段階強化 |
| 個人/小規模運用の保守負担 | 相場収集を絞る、マネージドサービス活用、機能を欲張らない |
| 競合（hobipedia, マイカ漫画展開） | 「管理×相場の統合」「コンディション別相場」「自分の蔵書に紐付く資産ビュー」で差別化 |
| 収益化の遅れ | 無料＋アフィリで低コスト運用、有料化は習慣化後（`07`） |
