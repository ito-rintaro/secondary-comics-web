# 02 スコープ / MVP / フェーズ分け

## 基本戦略

現デモ（クライアント完結・ダミー相場）を、**「①サーバ/DB化 → ②認証 → ③相場の実データ化」**の順で本番化する。
相場データ源が未定（`04_market_data.md`）なため、**相場の実データ化を待たずに進められる部分（管理機能のサーバ化）から着手**し、相場は段階的に差し替える。

## フェーズ0：デモ（現状・完了）

- 単一HTML、localStorage、ダミー相場。コンセプト検証済み。

## フェーズ1：MVP（最小本番）— 目標：管理機能を「本物のWebサービス」に

含むもの（すべて P0）:

- FR-C1/C2/C4 認証・クラウド保存・退会
- FR-A1〜A7 コレクション管理一式（デモ機能をサーバ実装へ移植）
- FR-B1/B2 相場表示・チャート（**ただしデータは暫定**：当面はユーザー手入力 or 限定的な合法データ源）
- FR-C3 デモJSONの取込

含まないもの：アラート、ランキング、売買、週刊誌相場。

**MVPの相場の扱い**：本格的な自動相場収集は `04` の決定待ち。MVPでは「現在相場＝ユーザー手入力（デモ同様）＋将来差し替え可能な設計」とし、`market` 値の出所を `source` フィールドで区別できるようにしておく（`03_data_model.md`）。

## フェーズ2：相場の実データ化

- `04_market_data.md` で選んだデータ源を実装（バッチ収集 or API連携）。
- FR-A8 現在相場の自動反映、FR-B3 コンディション別相場、FR-A9 資産推移グラフ。
- FR-B4 ランキング・トレンド。

## フェーズ3：エンゲージメント

- FR-B5 価格アラート、FR-B6 ウォッチリスト、通知基盤（メール/プッシュ）。
- 記事コンテンツ（hobipedia的な「プレミア検出」「仕入れリスト」）→ 集客/SEO/収益化の土台。

## フェーズ4：拡張（要再判断）

- FR-B7 週刊誌相場、複数コレクション、CSV。
- マーケットプレイス化（ユーザー間売買・委託・手数料）＝ 別途事業判断（`07_business.md`）。スマホアプリ化もここで検討。

## MoSCoW（MVP内）

| 区分 | 項目 |
|---|---|
| Must | 認証、クラウド保存、コレクションCRUD、サマリー、検索/フィルタ/ソート、エクスポート/インポート、退会 |
| Should | 相場表示（暫定データ）、チャート、写真添付 |
| Could | コンディション別表示の素地、相場source区別 |
| Won't（今は） | 売買・決済、アラート、週刊誌相場、ネイティブアプリ |

## 未決により後ろ倒しにするもの

- **相場自動収集**（`04`決定待ち）
- **収益化施策**（`07`未定。MVPは収益機能なしで可）
